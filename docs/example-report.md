## 3. 主要发现

### [契约冲突] 因果链已标注证据等级，但换行后被判为未标注

- 功能：报告检查器的因果链证据标记校验。
- 合法任务与成功标准：按照审计方法第 5 节的多行箭头结构记录因果链，保留 [静态事实] 或 [模型推断] 标记；在其他必要字段均齐全时通过检查。
- 失败场景：证据标记放在 `- 因果链：` 的续行，检查器只读首行，返回“因果链必须标注 [静态事实] 或 [模型推断]”。
- 因果链：
  合法任务：提交带证据标记的多行因果链 [静态事实] audit-method.md:62–68
  → 检查器用 `(.*)$` 只提取字段首行 [静态事实] check_report.py:61
  → 续行标记未进入 `causal.group(1)` [静态事实] check_report.py:61–62
  → 追加“因果链必须标注”错误 [静态事实] check_report.py:63
  → CLI 因存在错误返回 1，合规格式被拒 [静态事实] check_report.py:86
- 门禁与保护依据：保护目标是报告证据可追溯性，依据为 [report-format.md:24](https://github.com/sinyookkkk/Gatecreep/blob/97bb54ca4fd70af328170af8cd9ba59ed444725d/gatecreep/references/report-format.md#L24)。历史实现 [check_report.py:61–63](https://github.com/sinyookkkk/Gatecreep/blob/97bb54ca4fd70af328170af8cd9ba59ed444725d/gatecreep/scripts/check_report.py#L61-L63)把检查范围限制为首行，而 [audit-method.md:62–68](https://github.com/sinyookkkk/Gatecreep/blob/97bb54ca4fd70af328170af8cd9ba59ed444725d/gatecreep/references/audit-method.md#L62-L68)展示多行结构。契约要求标注，并未要求标记必须位于字段首行。
- 实际影响：同一报告仅调整因果链换行位置，历史检查器的结果从通过变为拒绝。用户需要压平符合方法文档的结构才能交付；没有证据表明它影响所有报告或所有用户。
- 反证检查：检查了“单行是机器读取约定”的解释。报告格式没有该要求，方法文档反而展示多行结构。保留证据校验有合理依据，但没有找到拒绝续行标记的契约依据。本条不建议取消证据检查。
- 不确定性：这是对确定性检查器的最小对照，不是第三方用户研究，也不证明其他 Markdown 结构都受支持。
- 置信度：高；同一输入内容仅改变换行位置，源码分支与结果一致。
- 调整方向：检查完整因果链字段的续行，止于下一个字段或发现；保留无标记时的拒绝，避免借用其他字段中的标记。

最小差异：

```markdown
- 因果链：合法输入 → 触发校验 [静态事实] → 报告被拒
```

与：

```markdown
- 因果链：
  合法输入
  → 触发校验 [静态事实]
  → 报告被拒
```

| 对照 | 历史检查器结果 |
|---|---|
| 单行；其他章节和字段相同 | 无校验错误，CLI 返回 0 |
| 多行；标记仍在因果链字段内 | 因果链标记错误，CLI 返回 1 |

以上片段需要放入完整报告；单独将片段交给检查器会因缺少必要章节而失败。
